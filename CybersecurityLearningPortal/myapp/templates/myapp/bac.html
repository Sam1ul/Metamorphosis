🔓 Broken Access Control

Broken Access Control occurs when users can access resources or perform actions they are not authorized to do. It is one of the most critical web security vulnerabilities.

What is Broken Access Control?

It happens when an application fails to properly enforce permissions. Attackers can access admin pages, user data, or restricted functions without proper authorization.

Memory Trick: No permission check = full access risk.

Why It’s Dangerous

  • Unauthorized data access
  • Admin panel exposure
  • Data theft or modification
  • Privilege escalation
  • System compromise

Types of Access Control Issues

  • Horizontal privilege escalation (access other users' data)
  • Vertical privilege escalation (becoming admin)
  • Insecure Direct Object Reference (IDOR)
  • Missing function-level access control

Examples

Example 1: IDOR

/user/profile?id=2
→ attacker changes id=3 and sees another user data

Example 2: Admin panel access

/admin/dashboard accessible without login check

Example 3: Role bypass

User manually changes role=admin in request

Common Attacks

  • URL manipulation
  • IDOR exploitation
  • Privilege escalation
  • Forced browsing

Prevention

  • Enforce strict access control checks
  • Use role-based access control (RBAC)
  • Validate every request on server side
  • Do not trust client-side checks
  • Protect all admin endpoints

Best Practices

  • Apply least privilege principle
  • Centralize access control logic
  • Log unauthorized attempts
  • Use secure session management
  • Regular security testing

For Exam Writing

Broken Access Control is a vulnerability where unauthorized users can access restricted data or functions due to missing or improper permission checks.

Summary

Access control ensures users only access what they are allowed to. If broken, it leads to serious security breaches including data leaks and privilege escalation.
