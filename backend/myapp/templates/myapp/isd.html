⚠️ Insecure Design

Insecure design refers to flaws in the application’s architecture or logic that make it vulnerable to attacks. These are not simple coding mistakes but deeper issues in how the system is planned.

What is Insecure Design?

It occurs when security is not considered during the design phase. Even if code is correct, poor design decisions can still make the system insecure.

Memory Trick: Bad design = built-in vulnerability.

Why It’s Dangerous

  • Cannot be fixed easily with patches
  • Leads to multiple vulnerabilities
  • May allow full system compromise
  • Exposes sensitive data

Common Causes

  • No threat modeling
  • Lack of security requirements
  • Trusting user input blindly
  • No rate limiting
  • Missing access control design

Examples

Example 1: No rate limit

User can try unlimited passwords → brute-force possible

Example 2: Business logic flaw

User changes price in request → buys product for $1

Example 3: No validation

User inputs anything → system accepts it

Possible Attacks

  • Business logic abuse
  • Privilege escalation
  • Brute-force attacks
  • Data manipulation

Prevention

  • Use threat modeling
  • Design with security in mind
  • Validate all inputs
  • Implement rate limiting
  • Use proper access control

Best Practices

  • Follow secure design principles
  • Use least privilege
  • Apply defense in depth
  • Regular security reviews
  • Test business logic thoroughly

For Exam Writing

Insecure design is a vulnerability caused by poor system architecture or logic, leading to security weaknesses even if the code is correct.

Summary

Security must be built from the design stage. Fixing insecure design later is difficult, so planning secure architecture is essential.
