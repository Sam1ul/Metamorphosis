Server-Side Request Forgery (SSRF)

What is SSRF?

Server-Side Request Forgery happens when an application allows a user to supply a URL and the server fetches that resource without proper validation. An attacker can abuse this to force the server to send requests to internal systems or services that are normally not accessible from outside.

Memory Trick: SSRF = attacker makes the server act like their browser.

How a Typical SSRF Attack Works

  1. The application accepts a URL from the user.
  2. The server makes a request to that URL.
  3. Validation is weak or missing.
  4. The attacker provides an internal address.
  5. Sensitive information is returned.

Example

A website allows users to import a profile picture using an image URL. The attacker submits: 

http://127.0.0.1/admin

The server accesses the internal admin panel and may leak private data.

Why SSRF is Dangerous

  • Access to internal APIs
  • Exposure of cloud credentials
  • Internal network scanning
  • Firewall bypass
  • Possible remote code execution

Common Targets

  • localhost
  • 127.0.0.1
  • 10.x.x.x / 192.168.x.x
  • 169.254.169.254 (cloud metadata)

Types of SSRF

Basic SSRF: Attacker receives the response.

Blind SSRF: Attacker cannot see the response but observes effects (DNS, delays).

Where SSRF Usually Appears

  • Image import from URL
  • Webhook systems
  • URL previews
  • PDF or screenshot generators

Prevention

  • Allowlist trusted domains
  • Block internal IP ranges
  • Disable dangerous protocols
  • Validate and normalize URLs
  • Protect internal services with authentication

For Exam Writing

SSRF is a vulnerability where an attacker tricks a server into making unauthorized requests to internal or external resources.
